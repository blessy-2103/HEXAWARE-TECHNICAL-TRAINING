
# Definition of Ready (DoR) and Definition of Done (DoD)

## Definition of Ready (DoR)

A user story is Ready for development when:

- [ ] The user story follows the As a / I want / so that format.
- [ ] The business value is clearly defined.
- [ ] Acceptance criteria are documented.
- [ ] The story satisfies INVEST principles.
- [ ] Dependencies are identified.
- [ ] The story is estimated using Planning Poker.
- [ ] The Product Owner has prioritised the story.
- [ ] The requirements are clear and understandable.
- [ ] The story is small enough to complete within a Sprint.

## Definition of Done (DoD)

A user story is Done when:

- [ ] Development is completed.
- [ ] Code review is completed.
- [ ] Unit tests are passed.
- [ ] Integration tests are passed where applicable.
- [ ] Acceptance criteria are satisfied.
- [ ] Booking and cancellation scenarios are tested.
- [ ] No critical or high-severity defects remain.
- [ ] User data and appointment information are protected.
- [ ] Documentation is updated where necessary.
- [ ] Changes are integrated into the agreed codebase.
- [ ] The functionality is verified and ready for demonstration or release.

## Purpose

The Definition of Ready ensures that Developers understand what needs to be implemented before starting work.

The Definition of Done ensures that every completed story meets the team's quality and acceptance standards.
