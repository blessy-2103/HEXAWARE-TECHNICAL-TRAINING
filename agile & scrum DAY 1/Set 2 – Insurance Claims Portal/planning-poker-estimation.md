## Fibonacci Story Point Scale

The team uses the following Planning Poker values:

1, 2, 3, 5, 8, 13

Story points represent relative effort, complexity, and uncertainty.

## Planning Poker Discussion

### Example Outlier Discussion – US05 Upload Supporting Documents

Initial estimates:

- Developer A: 3 points
- Developer B: 5 points
- Developer C: 8 points

### Reason for Difference

Developer A considered only basic file upload.

Developer B considered file upload, file type validation, and file size restrictions.

Developer C considered additional complexity such as upload failures, storage integration, and security validation.

### Discussion and Resolution

The team discussed the acceptance criteria and agreed that the story should include file type validation and size restrictions but exclude advanced document processing.

The team agreed on 5 story points.

## Planning Poker Process

1. Product Owner explains the story.
2. Developers discuss scope and assumptions.
3. Developers select estimates privately.
4. Estimates are revealed simultaneously.
5. Outliers explain their reasoning.
6. The team discusses and votes again.
7. A consensus estimate is recorded.

## Estimation Note

These are illustrative estimates for the assignment. In an actual Scrum team, Developers determine estimates collaboratively.
