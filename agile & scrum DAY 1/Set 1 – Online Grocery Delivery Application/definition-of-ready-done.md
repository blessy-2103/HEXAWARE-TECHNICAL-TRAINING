
# Definition of Ready (DoR) and Definition of Done (DoD)

## Definition of Ready (DoR)

A user story is Ready for development when:

- [ ] The story is written in As a / I want / so that format.
- [ ] Business value is clearly defined.
- [ ] Acceptance criteria are documented.
- [ ] The story satisfies INVEST principles.
- [ ] Dependencies are identified.
- [ ] The story is estimated by Developers.
- [ ] The Product Owner has prioritised the story.
- [ ] The story is small enough to complete within a Sprint.
- [ ] Requirements are clear and understandable.

## Definition of Done (DoD)

A user story is Done when:

- [ ] Implementation is completed.
- [ ] Code review is completed.
- [ ] Unit tests pass.
- [ ] Integration tests pass where applicable.
- [ ] Acceptance criteria are satisfied.
- [ ] No critical or high-severity defects remain.
- [ ] Documentation is updated where necessary.
- [ ] Changes are integrated into the agreed codebase.
- [ ] Quality and security standards are met.
- [ ] The functionality is verified and ready for release.

## Responsibility

The Scrum Team collaboratively establishes and follows the Definition of Done.

The Developers are responsible for meeting the Definition of Done.

The Product Owner verifies that the product meets the agreed acceptance criteria.
