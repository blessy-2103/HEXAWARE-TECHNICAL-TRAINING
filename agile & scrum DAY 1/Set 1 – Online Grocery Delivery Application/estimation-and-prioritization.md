
# Estimation and Prioritisation

## MoSCoW Method

- Must Have: Essential features required for the release.
- Should Have: Important features that can be delivered later if necessary.
- Could Have: Useful features with lower priority.
- Won't Have: Features excluded from the current release.

## Fibonacci Story Point Scale

Planning Poker uses Fibonacci numbers:

1, 2, 3, 5, 8, 13, 21

Story points represent relative effort, complexity, and uncertainty rather than working hours.

## Reference Story

US01 – View Grocery Categories

Estimated Story Points: 2

### Justification

This story is selected as the reference story because it is simple, well understood, and has limited scope.

Other stories are estimated relative to this story.

## Planning Poker Process

1. Product Owner explains the user story.
2. Developers discuss requirements and complexity.
3. Each Developer selects a Fibonacci card privately.
4. All estimates are revealed simultaneously.
5. Differences in estimates are discussed.
6. Developers vote again until a common estimate is reached.

## Estimation Note

The story points shown are sample estimates for this assignment. In an actual Scrum team, Developers collaboratively decide the estimates during Planning Poker.
